# 语音输入 v11：卡死排查与稳定性改动

日期：2026-11-02 · 状态：v11 已在本机替换运行，本轮复核 30 项单元测试通过；真实口述与长时间稳定性待观察。

## 结论

旧版停止录音时整个应用无响应的问题已抓到现场。卡死的是主线程，死在停止录音这一步：PortAudio 和 CoreAudio 互相等锁。主线程一停，菜单栏、快捷键响应、浮条全部不动，只能强杀。v11 把录音从 sounddevice/PortAudio 换成自写的 AudioQueue 原生模块，开关麦全部移出主线程。另外补了一批会让状态卡在「录音中 / 识别中」的路径。

## 现场证据

本机复现后日志停止推进。对卡住的进程进行线程采样，看到两个线程互相等待对方的锁：

- 主线程：`stream.stop()` → `Pa_StopStream` → `AudioOutputUnitStop` → `HALC_ProxyIOContext::StopIOProc` → 等 `HALB_Mutex`。
- CoreAudio IO 线程：PortAudio 的 `startStopCallback` → `AudioUnitGetProperty` → 等 AudioUnit 的 `recursive_mutex`。

这是 PortAudio（sounddevice 0.5.6 自带 V19.7.0-devel）在 macOS 上的停流死锁，偶发，和录音长短无关。旧代码在主线程调 `stream.stop()`，所以一中招就整个 App 卡死。

## 改了什么

| 问题 | 证据 | v11 改法 |
|---|---|---|
| 停流死锁卡死主线程 | 上面的现场堆栈 | 新增 `src/audiorec.c`：AudioQueue 录音，系统直接给 16kHz 单声道 float，回调只拷数据、不碰 Python。`Recorder` 用一个专用 daemon 线程按顺序开关麦，主线程只拿 Future、从不等 |
| 开麦/关麦卡住后状态永远停在录音中 | 代码审查 | 开麦 5 秒没成功就作废这一段；关麦 5 秒拿不到音频就报错复位 |
| 识别卡住后永远停在「识别中」，再按快捷键只提示「还在识别」 | 代码审查：`model_ready.wait()` 无超时，MPS 推理没有上限 | 主线程看门狗：20 秒 + 录音时长×0.3（模型未加载再加 60 秒）没出结果就复位。迟到的结果不粘贴，放进「复制上次结果」。等模型最多 60 秒 |
| 主线程回调抛异常后状态卡死；PyObjC 默认弹出的错误框藏在后面，看着像卡死 | 代码审查：`runEventLoop` 默认 `unexpectedErrorAlertPanel` | 主线程入口加 `@guarded`：异常记日志、关麦、回到就绪。事件循环改用 `log_unexpected`，只记日志不弹框 |
| 目标 App 忙时，AX 查询最长卡主线程 6 秒×4 次 | 系统默认 AX 超时 6 秒 | 每个目标 App 元素设 `AXUIElementSetMessagingTimeout` 1 秒 |
| ChatGPT、Grok 里频繁「拿不到输入焦点，未插入」 | 实现阶段日志多次记录 Electron 应用焦点读取失败 | 开录时没拿到焦点的，插入时再读一次。读到可编辑、非密码框就粘贴；开录时拿到过焦点、后来换了的，照旧拦下 |
| 3 分钟以上的录音结尾被截掉 | qwen_asr 单段生成上限 1024 token，600 秒以内不自动切段；134 秒录音已出 526 字 | 识别前按 60 秒在低音量处切段，逐段识别后拼接，中英文边界补空格 |
| 中途换麦克风后录不到声音 | PortAudio 启动时缓存设备列表 | AudioQueue 每段新建，总用当时的系统默认麦克风。录到的比按住的时间短 2 秒以上时，日志记 `mic gap`，提示里写「录音中途断了约 N 秒」 |
| 加载失败后只能重启 | `error` 状态按快捷键只弹提示 | `error` 状态按快捷键重试加载 |
| 设置写到一半退出会留下坏 JSON，下次启动直接崩 | `save_setting` 直接覆盖写 | 先写临时文件再替换 |
| 键盘事件读线程遇到半条记录会崩，快捷键静默失效 | `iter_unpack` 在 try 外 | 半条留到下次拼上；管道读失败记日志 |
| pid 被别的进程复用时拒绝启动 | 只用 `kill -0` 判活 | 再核对进程命令行是不是 `voice_input.py` |
| 日志被 transformers 警告刷屏 | 每次识别一行 `generation flags are not valid` | 加载模型时把 transformers 日志调到 error |
| 外接屏切换瞬间 `NSScreen.mainScreen()` 为空，浮条报错 | 代码审查 | 为空时不重新定位 |

改动文件：`src/audiorec.c`（新）、`src/voice_input.py`、`src/overlay.py`（音量改为每帧从录音模块取）、`tests/test_units.py`。`requirements.lock` 里的 sounddevice 没删，代码已不再 import 它。

## 验证

以下真机验证结果由实现阶段记录提供；本次提交前独立重跑了单元测试，30 项通过，未重新进行麦克风和粘贴端到端测试。

- 单元测试 20 → 30 个，全过。新增的覆盖：原生缓冲区读写、长音频切段与拼接、正常录音到粘贴、开麦失败、开麦超时、识别看门狗与迟到结果、静音与断流提示、异常兜底复位、开录时没拿到焦点的放行规则。
- 原生录音单测：开麦 15–120 毫秒，关麦 2–15 毫秒，录到的时长和实际经过的时间一致。
- 真 App 端到端（合成按键 fn+A，TextEdit）：快速开关 8 次没有卡住，每次都正确回到就绪；Esc 取消正常；正常一段 7 秒录音 0.9 秒粘贴进 TextEdit。
- 识别文字有错字，也多出外放里没有的句子。原因是测试用扬声器外放，到麦克风只比底噪高一点（RMS 约 1%），屋里还有别的声音。这一项不算录音模块的问题，要靠真实口述确认。

## 独立审查

实现阶段的只读审查记录认为核心目标达成；实现者逐条对照代码处理了以下意见。本次提交前另外复核了录音线程、会话作废和焦点边界逻辑，并重新运行单元测试，30 项通过。以下历史真机结果来自实现阶段记录，本次未重新执行。

- **已修**：
  - 焦点放宽可能贴进同一 App 的另一个窗口。现在开录时没拿到焦点的，要求插入时的窗口和开录时一致，开录时连窗口都没拿到就照旧拦下。
  - AX 超时只设在 App 元素上，派生元素不一定继承。现在启动时在系统级元素上设全局 1 秒；开录取焦点的重试总共不超过 0.3 秒。
  - `set_state` 中途出错，原生层仍以为在录音，Esc 会一直被吞。现在先同步原生层，再更新界面。
  - 迟到结果的提示音会录进正在录的新一段，现在录音中不响。
  - 看门狗和模型等待超时的提示里加上「连续出现就从菜单退出再重开」。
  - 补了两条断言：换窗口不贴；开麦卡住时关麦请求已排进队列。
- **没修，原因是只有推测、没有证据**：剪贴板快照读别的 App 的惰性数据会阻塞主线程；闲置卸载时在主线程清 MPS 缓存，可能被卡死的旧识别线程拖住。
- **设计上接受**：`AudioQueueStop(q, true)` 会丢掉最后不满 50 毫秒的一块；模型加载线程卡死后只能退出重开。

## 复核重点与已知边界

**复核重点**（按风险排序）：

1. `audiorec.c` 的 AudioQueue 用法：`AudioQueueStop(q, true)` 后立即 `Dispose`、`running` 标志控制回调里不再 Enqueue，是否还有在 Dispose 后进回调的窗口。
2. `session` 计数作废过期计时器和迟到结果的逻辑：复位、取消、开麦失败三条路径都会递增，确认没有让正常结果被误判成迟到。流程测试把后台线程换成了当场执行，真实的异步先后顺序只靠真机跑过两轮。
3. `check_target` 放宽后的边界：开录时没拿到焦点，插入时同一窗口里任意可编辑框都会收到粘贴。

**没做、留给后续**：

- 上面「没修」的两条主线程阻塞点，等有日志证据再动。
- 关麦真卡死时（5 秒超时）只提示重启，没有自动重启进程。AudioQueue 至今没复现过卡死，先观察。
- 粘贴后 0.6 秒恢复剪贴板。慢的 Electron App 可能来不及读，贴进去的是旧剪贴板。没有日志证据，没改。
- 部分 fn 组合键会和 macOS 的 Globe 系统快捷键冲突，监听在会话层先吞掉了，目前没出问题。将来系统升级改了优先级，快捷键会失效。
- ChatGPT 桌面版的焦点放行是按 Grok 的现象推的，ChatGPT 本身没在真机上复测。
- 日志没有轮转，目前 48KB，增长慢，不急。
- `requirements.lock` 删掉 sounddevice 及其独占依赖，并重新生成锁文件。
