# Qwen3-ASR 语音输入 · 本机实测（2026-10-28）

识别链路已经能日常用：断网照常转写，35 秒的口述 2.2 秒出字，连续 10 次耗时和内存都不涨。跨 App 粘贴还没测。测试时屏幕锁着，快捷键和粘贴都发不进去。下面每项都写明测了什么、没测什么。

## 环境

- Apple M3 Max，36GB 统一内存，macOS 26.5.2。
- 后端：官方 `qwen-asr` 0.0.6 的 transformers 后端，PyTorch 2.14.1 走 MPS，bf16，transformers 4.57.6，Python 3.12。全部版本见仓根 `requirements.lock`。
- 模型：原版权重 SHA-256 复核一致。没转 MLX，也没量化。官方原版在 MPS 上已经够快，没必要换格式。

## 样本来源

测试音频由 macOS `say` 合成：中文用 Tingting，英文用 Samantha。合成音比真人口述干净，但 Tingting 念英文单词很差。所以下面的准确度只能说明链路正确，不能代表你自己说话时的准确度。真人样本没测。

## 延迟

只计识别耗时，不含粘贴。粘贴是一次剪贴板写入加一次按键，没单独测。

| 录音 | 识别耗时 |
|---|---|
| 3.9 秒 | 0.50 秒 |
| 16.9 秒 | 1.23 秒 |
| 35.1 秒 | 2.16 秒 |

- **冷启动**：工具启动后约 8–13 秒就绪，大头是 import torch。加载权重 1.5–3 秒，预热 0.2–3 秒。
- **不预热的代价**：首次识别要 10 秒，原因是 MPS 首次编译算子。工具启动时已用一段 2 秒噪声预热，就绪后第一次识别就是快的。
- 「按下结束键到文字出现」的端到端耗时，要等解锁屏幕后测。

## 内存

口径是 macOS `footprint` 的进程占用（phys_footprint）。它已经包含 MPS 在统一内存里分配的显存，不再另加 RSS，避免重复计数。

| 阶段 | 占用 |
|---|---|
| 只 import 完依赖 | 40MB |
| 加载并预热后待机 | 2.53–2.68GB |
| 跑完 8 段样本后 | 2.85GB |
| 再连续识别 10 次 | 2.847–2.851GB，不涨 |
| 退出后 | 进程结束，全部释放 |

比「0.6B」听起来大。权重文件本身 1.88GB，含音频编码器，bf16；PyTorch 还会留缓存池。要压内存只能量化或换 MLX，都没测，收益不承诺。

## 准确度

| 样本 | 结果 |
|---|---|
| 中文 + 数字（会议、百分之十二点五） | 全对 |
| 中文 15 秒（期货复盘、一千二百美元） | 「回测」错成「回撤」，其余全对 |
| 英文 2 段（10:30、12.5 percent、300 basis points） | 全对，数字自动转成阿拉伯数字 |
| 中英混（Python、PyTorch、benchmark） | 「PyTorch」拆成「Py Torch」，「200」写成「两百」 |
| 运维术语（launchd、bootout、bootstrap、caffeinate） | 4 个错 3 个：launched、boot out、cabinet |
| 30 秒长句里的「GitHub、Obsidian、Claude Code」 | 识别成「g top of city n cloud code」，主要怪 Tingting 念英文太差 |
| 静音 3 秒 / 低噪声 3 秒 | 输出为空，没编造文字 |

加专有名词表（`config/vocab.txt`）后同一批样本重测：PyTorch、bootstrap、caffeinate、回测 4 处纠对，Obsidian 认出来了，但写成小写。GitHub 和 launchd 还是错。原本就对的样本没变差。

## 断网

用 `sandbox-exec` 禁掉全部网络后，加载模型并跑完全部样本和 10 次重复都正常。运行时不依赖任何联网资源。

## 跨 App 粘贴：未测

测试时屏幕锁着，合成的快捷键发不进去。日志证实那次没有误触发录音。以下项目都还没测：

- Obsidian 编辑区、浏览器普通输入框、聊天输入框（微信 / Slack 草稿）的实际粘贴；
- 录音中切 App、换焦点、密码框、不可编辑区域的拦截；
- 麦克风权限首次弹窗、权限拒绝、忙碌时再按快捷键；
- 用真人口述连续 10 次的端到端表现。

这些在代码里都有对应处理，但没有实测，不算通过。

## 已知风险

- 有的 App 不通过辅助功能暴露焦点控件，比如部分自绘界面的聊天软件。它们会被判成「拿不到焦点」而拒绝粘贴，只能从菜单手动复制。这是有意偏保守，宁可不粘也不粘错。实际有多少 App 中招，要等实测。
- 粘贴后 0.6 秒恢复剪贴板。目标 App 要是读剪贴板慢于 0.6 秒，会粘进你原来的剪贴板内容。实测时要留意。
